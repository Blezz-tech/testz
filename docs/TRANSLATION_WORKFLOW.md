# Рабочий процесс: перевод одной главы

Регламент для агента-переводчика (и человека-редактора) в этом репозитории. Пайплайн рассчитан на **1198 глав** и на то, что канон живёт в [Лор-Вики](../wiki/README.md), а не в голове переводчика.

> **Главное правило:** глава не переводится «с листа». Сначала досье сущностей из вики, потом перевод, потом обновление вики.

---

## Схема

```text
chapters/zh/NNNN.md + chapters/zh/index.json
        │
        ▼
[0] Проверка записи в реестре          ── duplicate / missing_stub → стоп
        │
        ▼
[1] dосье: wiki_tool.py scan           ── имена, топонимы, титулы, сноски
        │
        ▼
[2] Разведка новых сущностей           ── нет карточки? создать до перевода
        │
        ▼
[3] Проход 1: смысловой перевод        ── разметка кандидатов в сноски
        │
        ▼
[4] Проход 2: литературная редактура   ── синтаксис, ритм, регистр
        │
        ▼
[5] Примечания (1–6)                   ── фильтр трёх вопросов
        │
        ▼
[6] Обновление вики + build + check
        │
        ▼
chapters/ru/NNNN.md
```

---

## Шаг 0. Реестр глав

Открыть запись `NNNN` в [`chapters/zh/index.json`](../chapters/zh/index.json) и проверить `status`:

| `status` | Действие |
| :--- | :--- |
| `ok` | Переходить к шагу 1 |
| `duplicate` | Не переводить. Сослаться на `duplicate_of` |
| `missing_stub` | Текста нет в источнике (`正在手打中…`). Сообщить пользователю и пропустить |

Поле `entry_type` задаёт тон: `chapter` — художественное повествование, `foreword` / `author_note` / `author_notice` — прямая речь автора к читателю, без стилизации под роман.

**Особые файлы** (см. [оглавление корпуса](../chapters/zh/README.md)):

- `0000_synopsis.md` — аннотация, не глава;
- `0000.md` — авторское предисловие;
- `0351.md`, `0936.md` — заглушки;
- `0749.md` (`= 0748`), `0942.md` (`= 0941`) — дубликаты.

## Шаг 1. Досье сущностей

```bash
python3 scripts/wiki_tool.py scan chapters/zh/NNNN.md --max-chapter NNNN
```

Что делает команда:

- находит в китайском тексте все `zh` и `zh_aliases` из вики;
- группирует по типам: персонажи, фракции, локации, культивация, артефакты, идиомы;
- считает вхождения и показывает, у кого `needs_endnote: true` — **[НУЖНА СНОСКА]**;
- отсекает карточки с `first_chapter > NNNN` — анти-спойлерный фильтр.

**Что делать с досье:**

1. Открыть каждую карточку и прочитать `## Правила перевода` (для персонажей — ещё и «Характер речи» и матрицу «ты / вы»).
2. Составить список сносок на главу (черновой).
3. Проверить, нет ли в тексте сущностей, которых сканер не увидел: сканер ищет по точным строкам, поэтому новые имена он пропускает **всегда**.

### Анти-спойлерное правило

При переводе главы `N` допустимо использовать только:

- каноническое имя и его варианты;
- пол и правила склонения;
- факты из хронологии с пометкой `<= N`;
- регистр речи, известный к главе `N`.

Запрещено: титулы, тайны происхождения, поздняя интонация, ранги, полученные позже. Если карточка содержит `<details>` с порогом выше `N` — **не открывать**.

## Шаг 2. Разведка новых сущностей

Просмотреть главу целиком и выписать:

1. **Новые имена** — прочитать каждый иероглиф, определить пол по контексту, проверить, нет ли «говорящего» имени. Проверить чтение по Палладию вручную: ошибки в чтении редких иероглифов типичны (`瀺` — *чань*, `邛` — *цюн*, `懋` — *мао*).
2. **Новые топонимы, секты, артефакты, техники** — подобрать перевод в стиле уже существующих карточек.
3. **Идиомы и культурный пласт** — разложить по трём корзинам:
   - бытовые чэнъюй → переводить идиоматично, **без сноски**;
   - сехоуюй → сохранять образ, сноска по ситуации;
   - обряды, календарь, скрытые цитаты → **сноска обязательна**.

**Правило нулевого шага:** если в главе появляется значимая новая сущность, карточка создаётся **до** первого абзаца перевода. Иначе имя будет придумано дважды — в тексте и в вики.

---

## Шаг 3. Проход 1 — смысловой перевод

1. Переводить **с китайского**, не через английский.
2. Строго держать термины из вики: ступени, философские категории, топонимы, обращения.
3. Восстанавливать опущенные подлежащие, но **не добавлять** причинно-следственных связок, которых нет у автора.
4. Ставить маркеры сносок `[^1]`, `[^2]` в отобранных местах.
5. Не сглаживать: если герой говорит грубо, коряво или по-детски — так и переводить.

---

## Шаг 4. Проход 2 — литературная редактура

Читать как русский редактор, сверяясь с [методикой](TRANSLATION_BEST_PRACTICES.md):

1. **Синтаксис** — разбить периоды на 2–4 предложения, убрать канцелярит («осуществил удар», «являющийся», «будучи»), но сохранить намеренную недоговорку.
2. **Ритм** — в кульминациях проверить число «ударов» (см. кредо одного меча, [идиомы](../wiki/idioms/one-sword-credo.md)); стихи и приговорки — ритмизовать.
3. **Лексика** — проверить на русизмы («вершки», «попы», «гроши»), кальки («обнял кулак», «друг по Дао») и сленг.
4. **Диалоги** — прочитать вслух. Если реплики двух персонажей можно поменять местами без потерь — голоса не найдены.
5. **Регистр** — сверить каждую пару говорящих с матрицей в карточке. Смена «вы» → «ты» должна быть событием.

---

## Шаг 5. Примечания

1. Никаких пояснений внутри абзацев — только надстрочные индексы.
2. Прогнать каждую заготовку через фильтр трёх вопросов (см. [методику, §5](TRANSLATION_BEST_PRACTICES.md#5-сноски-фильтр-трёх-вопросов)).
3. Оставить **1–6** сносок. Ноль — приемлемо.
4. Оформить в конце файла:

```markdown
---
### Примечания

[^1]: **惊蛰 (Цзинчжэ)** — «Пробуждение насекомых», третий сезон солнечного календаря.
```

5. Проверить, что ни одна сноска не раскрывает будущие главы.

## Шаг 6. Обновление вики

### 6.1. Новые карточки

Создать по шаблонам [`wiki/_templates/`](../wiki/_templates/):

| Тип | Шаблон | Папка |
| :--- | :--- | :--- |
| Персонаж | `character.md` | `wiki/characters/` |
| Локация | `location.md` | `wiki/locations/` |
| Ступень / техника | `cultivation.md` | `wiki/cultivation/` |
| Идиома | `idiom_allusion.md` | `wiki/idioms/` |
| Фракция / артефакт / концепт | `general_entity.md` | `wiki/factions/`, `wiki/artifacts/`, `wiki/concepts/` |

Обязательный минимум карточки: **инфобокс**, **«Правила перевода»**, **описание без спойлеров**, **три перекрёстные ссылки**.

### 6.2. Правки существующих

- Новое прозвище → в `zh_aliases` / `ru_aliases`.
- Новый факт → в хронологию, **внутрь `<details>`** с номером главы.
- Новый собеседник → в матрицу «ты / вы».
- Изменение отношений → отметить главу и обновить обе карточки (двусторонняя ссылка).

### 6.3. Сборка и проверка

```bash
python3 scripts/wiki_tool.py build   # пересобрать wiki/_index.json
python3 scripts/wiki_tool.py check   # YAML, типы, битые ссылки, дубли, заглушки
python3 scripts/wiki_tool.py index   # перегенерировать wiki/INDEX.md
```

`check` должен пройти **без ошибок**. Предупреждения о дублях `zh` разбираются: либо это подстраница (`parent`), либо ошибка — один ключ не должен вести к двум сущностям.

### 6.4. Файл перевода

Перевод сохраняется как `chapters/ru/NNNN.md`:

```markdown
---
chapter: 512
title_zh: 第五百一十二章 标题
title_ru: Название главы
status: draft | edited | final
endnotes: 3
---

# Глава 512. Название главы

…

---
### Примечания

[^1]: …
```

## Быстрый справочник команд

```bash
# досье главы
python3 scripts/wiki_tool.py scan chapters/zh/0512.md --max-chapter 512

# найти сущность
python3 scripts/wiki_tool.py lookup 落魄山
python3 scripts/wiki_tool.py lookup "Гора Лопо"

# проверить и пересобрать
python3 scripts/wiki_tool.py build && python3 scripts/wiki_tool.py check

# оглавления
python3 scripts/wiki_tool.py index
```

---

## Что считать готовой главой

Глава готова, если:

1. `check` проходит без ошибок;
2. все новые сущности имеют карточки;
3. сносок 1–6 и все они прошли фильтр;
4. регистр и голоса сверены с вики;
5. в файле перевода проставлен `status: edited`.

Дальше — только вычитка человеком-редактором, которая может менять формулировки, но **не канон**.
