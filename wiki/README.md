# Лор-Вики новеллы 《剑来》 (`wiki/`)

Эта папка — **единая база знаний (Lore Bible / Fandom Wiki)** для перевода романа Фэнхо Сичжухоу 《剑来》. Она спроектирована так, чтобы одновременно решать две задачи:

1. **Для человека (переводчика, редактора, читателя):** работать как полноценная вики в духе *Fandom / Obsidian* с перекрёстными кликабельными ссылками прямо в GitHub, VS Code или любом генераторе статических сайтов (Quartz, VitePress, MkDocs).
2. **Для AI-пайплайна перевода:** иметь строгий машиночитаемый заголовок (YAML frontmatter) и автособираемый индекс `wiki/_index.json`, позволяющий за миллисекунды находить в китайском тексте главы всех персонажей, топонимы, уровни культивации и аллюзии — без загрузки всей базы в контекст и **без спойлеров из будущих глав**.

---

## Почему не один гигантский `glossary.json`?

На дистанции в **1198 глав** плоская таблица «термин → перевод» перестаёт работать по четырём причинам:
1. **Множественные имена и титулы:** один персонаж имеет имя при рождении (`陈平安`), локальное прозвище, официальную должность (`隐官`), цеховое обращение (`小师叔`) и эпитеты.
2. **Граф отношений и регистр «ты / вы»:** в русском переводе критично помнить, кто кому говорит «ты», а кто «вы», и с какой интонацией. Это граф связей между карточками персонажей, а не строка в словаре.
3. **Защита от спойлеров (Хронологическое версионирование):** если в карточке героя в первой строке написать его титул из 900-й главы, переводчик (особенно LLM) невольно перенесёт позднюю интонацию в ранние главы. Поэтому неизменяемые правила перевода отделены от раздела `## Хронология по главам`.
4. **Сквозные рефрены и аллюзии:** Фэнхо Сичжухоу возвращает одни и те же стихи, поговорки и названия переулков спустя сотни глав. Хранение карточек идиом и топонимов с перекрёстными ссылками гарантирует, что рефрен будет узнан и переведён теми же словами.

## Структура каталогов `wiki/`

```text
wiki/
├── README.md                  # Описание архитектуры и правил ведения вики
├── _index.json                # Автоматически собираемый индекс (НЕ редактировать вручную)
├── _templates/                # Шаблоны новых карточек по категориям
│   ├── character.md           # Шаблон персонажа
│   ├── location.md            # Шаблон локации / топонима
│   ├── cultivation.md         # Шаблон ступени / пути культивации / техники
│   ├── idiom_allusion.md      # Шаблон идиомы, сехоуюй, обычая или цитаты
│   └── general_entity.md      # Шаблон фракции, артефакта или концепта мира
├── characters/                # Имена собственные: люди, духи, божества, демоны
├── locations/                 # Топонимы: миры, материки, грот-небеса, города, переулки
├── cultivation/               # Ступени совершенствования, пути (練气士, 武夫, 剑修), техники
├── concepts/                  # Философия Трёх Учений (道理, 本心, 气运), устройство мира
├── factions/                  # Династии, секты, академии, кланы
├── artifacts/                 # Мечи, сокровища, талисманы, трактаты
└── idioms/                    # Значимые идиомы, недоговорки (歇后语), обряды, поэзия
```

## Схема карточки и правила перекрёстных ссылок

Каждая статья состоит из двух слоёв:

### Слой 1. Структурированный YAML-заголовок (для скриптов и поиска)
```yaml
---
id: char.chen-pingan
type: character
zh: 陈平安
zh_aliases: ["平安", "陈公子", "小师叔"]
pinyin: Chen Ping'an
palladius: Чэнь Пинъань
ru: Чэнь Пинъань
ru_aliases: ["Пинъань"]
gender: male
first_chapter: 0
tags: ["главный-герой", "нипинсян", "мечник"]
---
```
* `zh` и `zh_aliases` — точные китайские строки, по которым сканер `scripts/wiki_tool.py scan` автоматически обнаруживает сущность в сыром тексте главы `chapters/NNNN.txt`.
* `first_chapter` — номер файла главы первого появления (`0` = предисловие `0000.txt`, `1` = `0001.txt`). Позволяет отсекать будущие сущности флагом `--max-chapter`.

### Слой 2. Текст вики-статьи с перекрёстными Markdown-ссылками
* Для связей между статьями используются **стандартные относительные Markdown-ссылки**:
  * внутри одной папки: `[Сун Цзисинь](song-jixin.md)`
  * между категориями: `[Переулок Глиняных Кувшинов](../locations/niping-alley.md)`
* Почему обычные Markdown-ссылки лучше нестандартных `[[вики-скобок]]`: они нативно кликабельны в веб-интерфейсе GitHub, в редакторах кода и в Obsidian, а скрипт `scripts/wiki_tool.py` умеет автоматически проверять их целостность и вычислять **обратные ссылки (Backlinks — «Упоминается в статьях»)** в `wiki/_index.json`.

## Инструменты работы с вики (`scripts/wiki_tool.py`)

```bash
# 1. Пересобрать поисковый индекс wiki/_index.json и граф обратных ссылок
python3 scripts/wiki_tool.py build

# 2. Проверить все карточки на битые перекрёстные ссылки и дубли китайских ключей
python3 scripts/wiki_tool.py check

# 3. Просканировать китайскую главу перед переводом (с защитой от спойлеров)
python3 scripts/wiki_tool.py scan chapters/0001.txt --max-chapter 1
```
