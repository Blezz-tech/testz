# 08. Железо и VRAM

## 8.1. Зачем железо игроку

Из концепта: «с определённого этапа можно купить железо и у себя запустить нейронку, но опять же дешманскую, т.к. у видюхи не VRAM». Железо — это:

1. **Локальный инференс** (бесплатные «токены», но электричество и время).
2. **Потолок VRAM** — определяет, какая модель вообще запустится.
3. **Второй кран расходов** — электричество, износ, ремонт.

## 8.3. VRAM: как работает (и как показывается)

Правила загрузки модели:

```python
model_vram_need = model_params_B * bytes_per_param_quant   # 3B → ~2.5 ГБ (q4), 13B → ~8 ГБ, 72B-q → ~22 ГБ
if model_vram_need <= gpu_vram:
    load_ok = True      # полная скорость
else:
    load_ok = False     # «не влезло»: своп на CPU/ОЗУ → скорость ×0.15, качество −20%
```

- **VRAM-виджет обязателен** (концепт): постоянная полоска в UI вида `VRAM: 5.2 / 8.0 ГБ`, с сегментами: «модель», «контекст проекта», «запас».
- Перегрузка VRAM (модель + контекст > 100%) → **троттлинг**: `event_mult ×0.7`, генерация медленнее, вентиляторы воют (аудио-флейвор).
- Контекст проекта (сложность заказа) тоже ест VRAM: тир 4 «тяжелит» на +1–2 ГБ.

Визуал виджета (см. [12](12-art-ui.md)):

```
┌─ VRAM ──────────────────────────┐
│ [██████████░░░░░░░░] 5.2/8.0 ГБ │
│ модель ▓▓▓▓▓▓  контекст ▓▓  free│
└─────────────────────────────────┘
```

## 8.4. Электричество

```python
gpu_hours     = часы активной локальной генерации (включая фоновую)
kWh_per_day   = (gpu_tdp * gpu_hours + base_pc_load * 24) / 1000
elec_bill_day = kWh_per_day * tariff * (1 - 0.03 * lvl_hardware)
```

| Железо | TDP | День активной генерации (8 ч) | Счёт за свет/день (тариф $0.05) |
| :--- | :--- | :--- | :--- |
| Стартовый ПК (без GPU) | 60 Вт | — | ~$0.07 |
| + Гаражная | 100 Вт | 0.86 кВт·ч | ~$0.11 |
| + Домашняя | 250 Вт | 2.4 кВт·ч | ~$0.19 |
| + Фермерская | 450 Вт | 4.0 кВт·ч | ~$0.27 |
| 2× Фермерская | 900 Вт | 7.7 кВт·ч | ~$0.45 |

Кажется копейками? В игровом балансе тариф растёт ивентами, а «ферма» гоняется 24/7 (фоновая генерация) — счёт за свет к концу игры сравним с арендой API. Именно это и задумано: **электричество — скрытая подписка на свои же железки**.

## 8.5. Локальная генерация: скорость

| Модель | Время «единицы работы» (на базе need=60) | Фоновый режим (×0.2) |
| :--- | :--- | :--- |
| H0 (3B) | 40 сек | 3 мин 20 сек |
| H1 (13B) | 25 сек | 2 мин 5 сек |
| H2 (72B-q) | 15 сек | 1 мин 15 сек |

- Активная генерация — игрок ждёт с прогресс-баром (можно «уйти», пойдёт фоном).
- Фоновый режим — основа офлайн-прогресса ([02](02-core-loop.md) §2.4).

## 8.6. Износ и ремонт

- Каждая единица локальной генерации копит `wear` (0.01/единицу).
- `wear > 100` → риск ивента «сгорела карта»: ремонт 20–40% стоимости GPU, простой 1–2 дня.
- «Чистка/термопаста» ($20) сбрасывает wear на 50 — маленькая, но важная кнопка обслуживания.

## 8.7. Апгрейды уровня жизни и ПК

| Уровень | Стол/рабочее место | Бонус |
| :--- | :--- | :--- |
| L0 | Картонка на коленях | −энергия/день, −скорость правок |
| L1 | Стол с барахолки | Базово |
| L2 | Нормальный стол + 2 монитора | +10% скорость работы, +настроение |
| L3 | Эргокресло, стол-стойка | +10% восстановление здоровья, −«спина» ивенты |
| L4 | Студия (комната-серверная) | +слот второй генерации, «мультитаск» |

## 8.8. Когда игрок переходит на локальное (экономический смысл)

```python
# точка безубыточности GPU:
days_to_roi = gpu_price / (daily_api_spend - daily_elec_cost)
# Гаражная $150 при API-расходе $12/день и свете $0.11/день → ~12.6 дней
```

- Геймдизайн-цель: GPU окупается за 8–12 дней **активного** использования; если игрок ленится гонять локальную модель — не окупается никогда.
- Второй смысл: локальная модель снимает зависимость от «биржи токенов» (инфляция ивентов бьёт по API, не по локалу).

## 8.9. UI-требования к железу

1. **VRAM-полоска** — всегда видна на экранах генерации и на главном экране (условие из концепта).
2. Карточки GPU в магазине: VRAM / TDP / «какую модель тянет» — тремя большими цифрами.
3. Экран «Железо»: схема системного блока (мультяшная), куда «вставляются» апгрейды (визуальная мотивация, как в PC Building Simulator-lite).
4. Счётчик электричества: «сегодня сожрал X кВт·ч (≈ $Y)» с иконкой лампочки.
