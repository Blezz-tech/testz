# 04. Нейронки и генерация

## 4.1. Модель как инструмент

Нейронка в Wibecoder — **не «кнопка сделай хорошо»**, а станок, у которого три ручки:

1. **Какая модель** (тир, качество отдачи, цена токена, потребление).
2. **Сколько токенов** (бюджет генерации).
3. **Куда токены** (подсистемы проекта).

Качество модели определяется **количеством потребляемых токенов**: дорогие модели на единицу работы жрут больше токенов (они «многословны»), но отдают больше качества за каждый токен. Дешёвые — жрут мало, но и отдача мизерная. Это главная экономическая ловушка игры: **«экономия на токенах» обходится дороже переделок**.

## 4.2. Тир-лист моделей (канонический)

| ID | Название | Способ доступа | Qm (качество) | Потребление токенов | Цена токена $/1k | Когда открывается |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| `L0` | **Лампочка-0.5** | Стартовая, API дешманский | 8 | ×0.7 | $0.10 | Старт |
| `L1` | **Шмодель** | API-подписка | 18 | ×0.9 | $0.25 | День 2 |
| `L2` | **Среднячок-1** | API-аренда | 32 | ×1.1 | $0.60 | Тир 2 заказов |
| `L3` | **Среднячок-2** | API-аренда | 48 | ×1.3 | $1.40 | Середина игры |
| `P1` | **ТурбоПлюс-Про** | API топ-провайдера | 65 | ×1.6 | $3.20 | Репутация 50+ |
| `P2` | **ТурбоПлюс-Про Max** | API топ-провайдера | 80 | ×2.0 | $7.00 | Босс-заказ №3 |
| `H0` | **Гаражная-3B** | Локально (GPU 4 ГБ) | 20 | ×1.0 (токены=время) | $0 (+электричество) | Куплен GPU |
| `H1` | **Домашняя-13B** | Локально (GPU 8–12 ГБ) | 38 | ×1.2 | $0 (+электричество) | GPU + скилл «Железо» |
| `H2` | **Фермерская-72B-q** | Локально (GPU 16–24 ГБ / 2×GPU) | 58 | ×1.4 | $0 (+электричество) | Ферма |

- `Qm` — потолок качества за токен (максимум формулы прироста, см. §4.4).
- **Потребление** — множитель: сколько токенов модель тратит на ту же единицу работы.
- У локальных моделей «токены» бесплатны, но генерация занимает **время** (см. [08](08-hardware.md)) и жрёт **электричество**.
- Дешманские модели (L0–L1) имеют повышенный `error_rate` (косяки) — это «хуёвая нейронка» из концепта.

## 4.3. Токены

- **Токены — расходник, не валюта**: купил → влил в генерацию → сгорели. Накопить «миллиард токенов на пенсию» нельзя — рынок двигается (см. [07](07-economy.md), инфляция цен).
- API-модели: токены **покупаются пакетами** (см. [14](14-balance.md), «Пакеты токенов»). Оптом дешевле, но пакеты «сгорают» через 14 игровых дней (провайдер «обновляет условия» — сюжетная маска ротации баланса).
- Локальные модели: токены считаются «виртуальными» (единица работы = время GPU), экономика смещается в электричество и износ.
- UI: счётчик токенов в шапке, при нуле — красная плашка «нейронка голодная».

## 4.4. Формула прироста качества подсистемы

Каноническая формула (реализация — [13](13-tech-architecture.md), `QualitySystem`):

```python
# tokens      — токены, влитые в подсистему
# need        — базовая потребность подсистемы (из таблицы проекта × model_consumption)
# Qm          — качество модели (см. §4.2)
# skill_mult  = 1 + skill_prompting * 0.06        # «как отпиздить нейронку», макс. ур. 20 → ×2.2
# event_mult  = product(модификаторов статов/ивентов)  # усталость, стресс, раш и т.д.
# rand        = uniform(0.90, 1.10)

token_mult = 1 - exp(-tokens / need)     # убывающая отдача, насыщение ≈ need
q_gain = Qm * skill_mult * token_mult * event_mult * rand
q_i = clamp(q_i + q_gain, 0, 100)
```

Ключевые свойства:

- **Убывающая отдача**: насыщение около `need`. Перекорм (tokens ≫ need) — деньги на ветер (максимум ещё +~2% к потолку).
- **Недокорм** (tokens ≪ need) — почти нулевой прирост: «влей хоть что-то, иначе нейронка даже не поймёт ТЗ».
- `need` растёт с тиром проекта и множителем потребления модели: **дорогая модель на сложном проекте жрёт токены как не в себя**.
- У дешманских моделей `Qm` маленький: даже полный бак токенов не даст качество, нужное для тира 3+.

## 4.5. Косяки и правки

Каждая генерация может породить **косяки** (баги, кривой арт, «музыка — это шум»):

```python
error_rate = base_error(model)          # L0: 0.35, P2: 0.04, H0: 0.30 ...
error_rate *= (1 - 0.04 * skill_debug)  # скилл «Правка/дебаг»
error_rate *= (1 + 0.5 if rush_mode else 1)
bugs_count = round(subsystem_volume * error_rate * rand(0.7, 1.3))
```

Механика правки (активная, по духу — «поймал косяк, чини»):

| Действие | Стоимость | Результат |
| :--- | :--- | :--- |
| **Починить руками** (мини-игра: тайминг-клик / «выбери правильный фрагмент кода») | Время игрока (5–15 сек), −энергия | Косяк устранён, +немного XP «Правки» |
| **Перегенерировать** (влить токены) | 30% от `need` подсистемы | Косяк устранён вероятностно (70%) |
| **Оставить как есть** | 0 | −к подсистеме «код/качество» (штраф `−bugs_left * 3` к итогу) |

Незакрытые косяки влияют на приёмку: `Q_final = Q_total − 3 * bugs_left` (см. [05](05-quality.md)).

## 4.6. Флейвор генерации (визуал процесса)

Генерация показывается как «работа нейронки» — это главный экран активности:

- **Лог генерации** («typing»-анимация): «Анализирую ТЗ... Нашёл 3 котика... Рисую графику... *Возможно, это код.*»
- **Полоски подсистем** параллельно наполняются (как в референсе — наглядный прогресс).
- У топовых моделей лог «умный» и быстрый (длинные фразы, меньше косяков); у Лампочки — обрывки фраз, ошибки в логе («Ошибка 42: не знаю, что такое “котики”»).
- При локальной модели — оверлей «GPU: 94%, VRAM 5.2/8.0 ГБ, вентилятор воят».

## 4.7. API vs локально: сравнение для игрока

| | API-модели (L/P) | Локальные (H) |
| :--- | :--- | :--- |
| Цена за работу | Деньги за токены (постоянно) | Электричество + износ (разово купил железо) |
| Скорость | Мгновенно (по клику) | Реальное время (секунды–минуты на единицу) |
| Ограничение | Баланс токенов | **VRAM** (какая модель влезает), TDP |
| Качество за деньги | Растёт с тиром модели | Потолок ниже (топ-провайдеры всё равно лучше) |
| Риск | Инфляция цен, «провайдер поднял цены» (ивент) | Сгоревший GPU, отключение света (ивенты) |

Тактический смысл: **API — это манёвренность и качество, локальное — это «перестать платить ренту»**. Оптимальная стратегия средней игры — гибрид: локальная модель «на каждый день», дорогой API «на сдачу важного проекта».

## 4.8. Подсистемы «генерации»: один станок, разные флейворы

Механически генерация графики, музыки, кода — одна система (токены → `q_gain`), но подаётся по-разному:

| Подсистема | Лог генерации | «Косяк» выглядит как |
| :--- | :--- | :--- |
| Графика | «Рисую спрайты...» | Кривая рука, лишние пальцы у кота |
| Музыка | «Собираю трек...» | Фальшивый луп, шум вместо бита |
| Код/Логика | «Пишу модули...» | Баг: «котик прыгает сквозь пол» |
| UX | «Собираю интерфейс...» | Кнопка «Назад» прячется за меню |
| Документация | «Формулирую требования...» | «Требование 2.3: сделать хорошо» |

## 4.9. Покупка и аренда моделей

- **Подписка/аренда** (API): ежедневная плата за доступ к тиру + токены сверху. «Доступ» можно отключить на паузу (не платишь, не используешь).
- **Покупка железа** (локально): разовая трата (см. [08](08-hardware.md)), дальше — электричество.
- **Важный момент баланса** (из концепта): на старте **нет «бесконечного апгрейда»** — каждая генерация стоит денег. «Подписка на всё и сразу» не работает: токены всё равно тратятся, и дорогие модели тратят их больше.
- «Пробный период» у новых моделей: 2 игровых дня с 50% скидкой (крючок, чтобы игрок попробовал и захотел вернуться).

## 4.10. Ограничения на стороне игрока

- Смена модели **во время проекта** возможна, но «переезд» стоит 10% уже набранного качества (нейронке надо «перечитать» проект).
- Одновременно можно генерировать **1 поток** (2-й поток — перк «Мультизадачность», скилл «Железо»).
- Каждая генерация имеет минимальный бак: `tokens ≥ 5% * need`, иначе «нейронка не поняла задачу» (0 прироста, но токены тратятся — жестокая, но честная школа).
