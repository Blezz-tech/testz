# 03. Система заказов

## 3.1. Источники заказов

| Источник | Как работает | Обновление |
| :--- | :--- | :--- |
| **Биржа** (основной) | 3–5 карточек заказов с визуальными вариантами. Обновляется каждые 2 игровых часа или кнопкой «Обновить» (стоит $2 на старте) | Авто + вручную |
| **Прямые заказчики** | Приходят по репутации: «Вас рекомендовали». Лучше оплата, но жёстче требования | 1 раз в 1–2 игровых дня |
| **Босс-заказы** (сюжет) | Майлстоуны: сайт для мэра, игра для издателя, САПР для завода. Огромная оплата, сложные ТЗ, открывают новый уровень жизни | По прогрессу |
| **Халтура от знакомых** | «Сделай лендинг за $20 и пиццу». Появляется при низком балансе (спасательный круг с дешёвой ценой) | Условно |

## 3.2. Карточка заказа (визуальный вариант)

Каждый заказ — **карточка**, как в референсе. Игрок сравнивает картинки и цифры, не текст:

```
┌──────────────────────────────────────┐
│ [иконка: 🎮 игра]  ТИР 1 · Халтура   │
│ ┌──────────────────────────────────┐ │
│ │  ПРЕВЬЮ (арт-мокап «ожидания»):  │ │
│ │  [мультяшный скриншот будущего   │ │
│ │   продукта заказчика]            │ │
│ └──────────────────────────────────┘ │
│ Заказчик: «Пазл про котиков»         │
│ 💰 $45        ⏳ 3 дн.        ⭐ 12  │
│ Требования:                          │
│   Графика ▓▓░░░  ≥25                 │
│   Геймплей ▓▓▓░░ ≥30                 │
│   Звук ▓░░░░ ≥15                     │
│ 💡 Совет: «Хватит Лампочки-0.5»      │
│        [ ВЗЯТЬ ]   [ ПРОПУСТИТЬ ]    │
└──────────────────────────────────────┘
```

- **Превью** — генерируемый (заранее заготовленный) мокап «как это видит заказчик». Визуально отличает тип и «уровень претензий» клиента.
- **Совет** — подсказка от системы («хватит Лампочки» / «нужна музыка ≥50 — бери модель с нормальным звуком»). Убирается в настройках хардкора.
- Цвет рамки карточки = тир (серый → зелёный → синий → золотой).

## 3.3. Типы проектов

Каждый тип — своя смесь **весов подсистем** (подробно в [05](05-quality.md)):

| Тип | Иконка | Доминирующие подсистемы | Флейвор генерации |
| :--- | :--- | :--- | :--- |
| **Игра** | 🎮 | Геймплей, графика, музыка | Лог «собираем игровой цикл», скрины уровней |
| **Сайт** | 🌐 | UX, графика (вёрстка), код | Лог «вёрстка секций», превью страниц |
| **Приложение** | 📱 | Код, UX, оптимизация | Лог «архитектура экранов», мокапы |
| **САПР** | ⚙️ | Код, документация, оптимизация (точность!) | Лог «расчётные модули», схемы/чертежи |

САПР — «тяжёлый» тип: низкая художественность, высокие требования к коду и докам, но самые дорогие заказы на тирах 3–4.

## 3.4. Тиры заказов

Эталонные числа — в [14](14-balance.md) (таблица «Заказы»). Сводка:

| Тир | Название | Оплата | Q_required | Дедлайн | Примеры |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 1 | Халтура | $20–120 | 15–30 | 2–3 дн. | Лендинг шаурмичной, пазл про котиков, сайт-визитка |
| 2 | Норм | $200–900 | 30–50 | 3–5 дн. | Магазин автозапчастей, мобилка-трекер привычек, платформер |
| 3 | Серьёзный | $1k–8k | 50–70 | 5–10 дн. | Игра для издателя, корп. портал, приложение банка |
| 4 | Корпоратив/САПР | $10k–100k | 70+ | 10–20 дн. | САПР для завода, симулятор, госзаказ |
| Босс | Сюжетный | фикс + бонус | 75+ | особый | «Сайт мэра», «Игра мечты», «Нейро-ферма» |

## 3.5. Требования заказа (ТЗ)

Помимо суммарного `Q_required`, у заказа могут быть **точечные требования** по подсистемам:

```json
{
  "requirements": {
    "total": 45,
    "sub": { "music": 50, "graphics": 40 }
  }
}
```

- Точечное требование `music ≥ 50` означает: при `music < 50` заказчик **не принимает** проект вовсе (или требует переделки — 1 бесплатная итерация правок).
- «Заказчик-перфекционист» (модификатор) повышает все требования на +5.
- «Заказчик-ленивый» снижает требования, но и платит −20%.

## 3.6. Дедлайны и просрочка

| Ситуация | Коэффициент оплаты | Репутация |
| :--- | :--- | :--- |
| Сдано в срок | ×1.0 (бонус ×1.15 за «досрочно и качественно») | +1…+3 |
| Просрочка < 25% дедлайна | ×0.7 | −1 |
| Просрочка 25–50% | ×0.4 | −3 |
| Просрочка > 50% | ×0.15, «заказчик ушёл в суд» (ивент) | −8 |
| Бросил заказ | Оплата 0, штраф −$50 (тир ≥2) | −10 |

Режим **«Раш»** (см. [02](02-core-loop.md)): ускорение ×2 на 1 игровой день, цена — −15% к качеству, −5 здоровья. Доступен 1 раз на заказ.

## 3.7. Выбор вариантов: где именно игрок решает

1. **Какой заказ взять** — визуальные карточки (главное решение).
2. **Каким проектом его делать** — при нескольких подходящих типах (редко: «заказчик хочет и игру, и сайт» → выбор фокуса).
3. **Сколько токенов влить и куда** — слайдеры по подсистемам (см. [04](04-generation-ai.md)).
4. **Какую модель использовать** — карточки моделей с ценой и VRAM.
5. **Править косяки или сдавать как есть** — «косяк стоит $X правки, но штраф к качеству».

Визуально каждое решение — карточки, кнопки, полоски. Никаких таблиц в момент выбора (таблицы — для доков, не для игрока).

## 3.8. Репутация заказчиков и игрока

- **Репутация игрока** (0–100): растёт за принятые проекты с высоким качеством, падает за просрочки и брошенные заказы.
- Влияет на: тир доступных заказов (порог), цену (множитель `1 + rep*0.005`), «дружелюбие» заказчиков (мягче дедлайны).
- **Клиенты-«любимчики»**: 3+ успешных заказа от одного заказчика → «постоянный клиент», +10% к оплате, персональные заказы.

## 3.9. Генерация пула заказов

```
refresh_pool():
  for slot in 0..pool_size:
    tier = weighted_pick(tier_weights_by_rep_and_progress)
    type = pick(project_types_available)
    order = make_order(tier, type)
    apply_modifiers(order)   # перфекционист, ленивый, срочный, «нужна музыка»...
  guarantee_at_least_one_affordable()   # страховка от пустого кошелька
```

- `tier_weights_by_rep_and_progress`: на старте 80% тира 1, 20% тира 2; с репутацией и пройденными боссами веса сдвигаются к 3–4.
- `guarantee_at_least_one_affordable()` — в каждом пуле есть хотя бы один заказ, оплата которого покрывает дневные расходы (анти-тупик).

## 3.10. Юмор заказов (примеры флейвора)

- «Сайт для автомойки. Заказчик: “нужно, чтобы как у конкурента, но лучше и дешевле”».
- «Мобильное приложение для учёта воды. Заказчик забыл, зачем ему вода».
- «Игра про пиксельных котов. Заказчик: “а можно как та, из рекламы, но без рекламы”».
- «САПР для завода. ТЗ — 217 страниц. Заказчик: “читать не обязательно, сделайте как там”».
