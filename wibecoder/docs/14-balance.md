## 14.8. Симуляция качества (пример, тир 2, игра)

```
need: graphics 108 (60×1.8), gameplay 126, music 90, code 144, ux 99, perf 81, docs 72
Модель L3 (Qm 48, ×1.3), skill_mult 1.36 (Promptsmithing 6), токены: gameplay 200, остальное по 80

token_mult(gameplay) = 1 - exp(-200/(126×1.3)) ≈ 0.71
q_gain(gameplay) = 48 × 1.36 × 0.71 ≈ 46.5 → q(gameplay) ≈ 47

token_mult(graphics) = 1 - exp(-80/(108×1.3)) ≈ 0.43
q_gain(graphics) = 48 × 1.36 × 0.43 ≈ 28 → q(graphics) ≈ 28
...
Q_total ≈ 0.25·28 + 0.30·47 + 0.20·33 + 0.15·40 + ... ≈ 38–42
```

Вывод для балансировщика: на L3 тир-2 проект «проходит» при skill 4–8 и баке ~800–1200k токенов; на L0-L1 — нет (потолок Qm слишком низкий). Это и есть «хуёвая нейронка vs нормальная».

## 14.9. Анти-тупик и подушки

- Всегда 1 доступный заказ, покрывающий дневные расходы ([03](03-orders.md) §3.9).
- «Халтура от знакомых» при балансе < $20.
- Подарок родителей (E21) при балансе < $20 (кулдаун 7 дней).
- ИБП и БП — «покупка-страховка» против худших ивентов.

## 14.10. Что крутить при балансировке

| Проблема | Крутить |
| :--- | :--- |
| «Скучно копить» | `payout` множитель, частота тира 2 на бирже |
| «Слишком легко» | `need` множитель, `error_rate`, цены пакетов |
| «Слишком дорого жить» | еда/ЖКХ ставки, инфляция |
| «GPU не окупается» | скорость H-моделей, тариф, цены API |
| «Ивенты бесят» | веса `weights` ([10](10-events.md) §10.4), кулдауны |
